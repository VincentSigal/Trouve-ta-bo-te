Documentation de l'API — Trouve ta boîte

Cette page explique comment utiliser l'API du site.

Pour utiliser cette API, envoie une requête HTTP à l'adresse :

http://localhost:3000/api

Toutes les réponses sont au format JSON. Les routes marquées Connexion requise ont besoin d'un header Authorization: Bearer <token>, obtenu via POST /users/login.

Liste des routes

  • GET /boites
  • GET /boites/:id
  • POST /boites
  • PUT /boites/:id
  • PATCH /boites/:id
  • DELETE /boites/:id
  • POST /boites/:id/click
  • GET /events
  • GET /events/:id
  • POST /events
  • PUT /events/:id
  • PATCH /events/:id
  • DELETE /events/:id
  • GET /users
  • GET /users/:id
  • POST /users
  • POST /users/login
  • PUT /users/:id
  • PATCH /users/:id
  • DELETE /users/:id

POST /boites

Connexion requise — owner ou admin

Description

Crée une nouvelle boîte. Elle est automatiquement attribuée à la personne connectée (un owner ne peut pas créer une boîte pour quelqu'un d'autre). city et music sont des noms en texte libre : s'ils n'existent pas encore en base, ils sont créés automatiquement.

Requête

{
  "name": "Le Panama",
  "siret": "12345678900011",
  "city": "Sète",
  "music": "House",
  "background": "/FRONT_END/img/panama/panama.webp",
  "logo": "/FRONT_END/img/panama/panama_logo.jpg",
  "location_link": "https://maps.app.goo.gl/...",
  "adress_name": "12 quai du port",
  "description": "...",
  "paragraph": "...",
  "tags1": "House",
  "tags2": "Festif",
  "age_min": 18,
  "age_max": 30,
  "price": 15,
  "instagram": "https://www.instagram.com/..."
}

Tous les champs sont facultatifs sauf name et siret (obligatoires en base). idCity peut être envoyé directement à la place de city si tu connais déjà son id.

Réponse

{ "message": "Boîte créée", "idClub": 24 }

Erreurs possibles

Code Cas
401 Pas de token / token invalide
403 Le compte connecté n'est ni owner ni admin
↑ Retour en haut

POST /events

Connexion requise — propriétaire de la boîte, ou admin

Description

Crée une soirée pour une boîte. Le champ music est facultatif : s'il n'est pas fourni, le style musical de la boîte organisatrice est repris automatiquement.

Requête

{
  "name": "Soirée Techno",
  "date_": "2026-08-01 23:00:00",
  "price": 15,
  "description": "Une nuit spéciale techno",
  "poster": "/FRONT_END/img/events/poster.jpg",
  "idClub": 1,
  "music": "Hardstyle"
}

date_ combine la date et l'heure dans un seul champ, au format YYYY-MM-DD HH:MM:SS.

Réponse

{ "message": "Soirée créée", "idEvent": 12 }

Erreurs possibles

Code Cas
401 Pas de token / token invalide
403 La boîte visée (idClub) ne t'appartient pas
404 Aucune boîte avec cet idClub
↑ Retour en haut

POST /users

Public

Description

Crée un compte. Si role vaut "owner", firstName, lastName et phone deviennent obligatoires.

Requête

{
  "email": "jean@club.fr",
  "password": "motdepasse123",
  "newsletter": false,
  "role": "owner",
  "city": "Montpellier",
  "firstName": "Jean",
  "lastName": "Dupont",
  "phone": "0611111111"
}

Le mot de passe est hashé avant d'être stocké (bcrypt). city fonctionne comme pour les boîtes : nom en texte libre, créé automatiquement si besoin.

Réponse

{ "message": "Utilisateur créé", "idUser": 8 }

Erreurs possibles

Code Cas
400 role = "owner" sans firstName/lastName/phone
409 Cet email est déjà utilisé
↑ Retour en haut

POST /users/login

Public

Description

Vérifie l'email et le mot de passe, et renvoie un token JWT à utiliser dans le header Authorization des routes protégées, sous la forme Authorization: Bearer <token>. Le token est valable 7 jours.

Requête

{
  "email": "jean@club.fr",
  "password": "motdepasse123"
}

Réponse

{
  "message": "Connexion réussie",
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "idUser": 1,
    "email": "jean@club.fr",
    "role": "owner",
    "firstName": "Jean"
  }
}

Erreurs possibles

Code Cas
401 Email ou mot de passe incorrect (même message dans les deux cas)
↑ Retour en haut

↑ Retour en haut

PATCH /users/:id

Public

Description

Modifie un utilisateur partiellement. Si le rôle passe à "owner", firstName/lastName/phone deviennent nécessaires (dans cette requête, ou déjà présents en base). Si le rôle passe à autre chose, les infos owner sont automatiquement supprimées.

Requête

{ "phone": "0699999999" }

Réponse

{ "message": "Utilisateur modifié" }

Erreurs possibles

Code Cas
400 Aucun champ valide, ou passage à owner sans firstName/lastName/phone
404 Aucun utilisateur avec cet id
409 Cet email est déjà utilisé
↑ Retour en haut
